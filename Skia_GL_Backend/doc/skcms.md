# skcms Transfer Function

## 1. 来源

`skcms_TransferFunction` 来源于 **ICC 国际色彩联盟规范**（ICC.1:2001-04, Section 6.5.11），即 ICC Profile 中 `para`（parametric curve）标签定义的参数化曲线类型。

skcms 是 Skia 内置的轻量色彩管理库，在 `modules/skcms/src/skcms_public.h` 中定义了该结构体和相关 API，直接实现了 ICC 标准中定义的参数化传输函数族，可覆盖 ICC 参数化曲线类型 0~4。

---

## 2. 作用

传输函数（Transfer Function）用于 **编码值 ↔ 线性值** 的相互转换：

- **EOTF（Electro-Optical Transfer Function）**：非线性编码值 → 线性光强度值。做色彩混合、色彩空间转换等物理正确运算前，必须先用 EOTF 把像素值“解压”回线性空间。
- **OETF（Opto-Electronic Transfer Function）**：线性光强度值 → 非线性编码值。是 EOTF 的逆函数，将运算结果“压缩”回存储/传输格式。

人眼对暗部变化更敏感，直接线性存储浪费码率，因此几乎所有色彩空间都使用非线性的传输函数。

## 3. 7 参数分段函数

```c
// skcms_public.h:39-48
typedef struct skcms_TransferFunction {
    float g, a, b, c, d, e, f;
} skcms_TransferFunction;
```

数学形式：

$$
y = \text{sgn}(x) \times
\begin{cases}
c|x| + f                &,\quad 0 \le |x| < d \\[10pt]
(a|x| + b)^g + e        &,\quad |x| \ge d
\end{cases}
$$

### 3.1 参数含义

| 参数 | 作用域   | 含义 |
|------|---------|------|
| **g** | 第二段   | gamma 指数。g > 1 压暗、g < 1 提亮。 |
| **a** | 第二段   | 线性缩放因子。在幂运算前对输入做线性拉伸/压缩，调制曲线坡度。 |
| **b** | 第二段   | 线性偏移量。在幂运算前对输入加偏移，使曲线不经过原点。 |
| **c** | 第一段   | 线性段的斜率。暗部用线性段替代幂函数，避免数值病态和噪声放大。 |
| **d** | 分段阈值 | 两段分界点。\|x\| < d 走线性段，\|x\| ≥ d 走 gamma 段。两段在 d 处需连续。 |
| **e** | 第二段   | 结果偏移量。对幂运算结果做整体平移，多数常用曲线中为 0。 |
| **f** | 第一段   | 线性段截距。让线性段可不经过原点，多数常用曲线中为 0。 |

### 3.2 最简形式：纯 gamma

$$
g = \gamma,\quad a = 1,\quad b = c = d = e = f = 0
$$

此时两段合并（d=0 永远走第二段），退化为 \(y = x^\gamma\)。

### 3.3 设计动机：为什么分段

纯 gamma 曲线在暗部附近导数趋近 0（g > 1 时），量化误差在暗部被严重放大。线性段提供有限斜率，保证暗部编码精度和噪声表现平稳。这个设计是 sRGB 标准的核心理念，被 ICC 采纳为通用参数化形式。

### 3.4 逆函数（OETF）

对 EOTF 的每个分支求逆：

**第一段（线性段）**：$(y = cx + f) → (x = (y - f)/c)，定义域 (0 \le y < cd + f)$

**第二段（幂段）**：$(y = (ax + b)^g + e) → (x = ((y - e)^{1/g} - b)/a)，定义域 (y \ge cd + f)$

两段在 $(y = cd + f)$ 处自然连续。

## 4. 各色彩空间参数对比

以下参数均来自 Skia 源码 `include/core/SkColorSpace.h` 中 `SkNamedTransferFn` 命名空间的实际定义值。

### 4.1 sRGB / Display P3

```
g = 2.4
a = 1 / 1.055   ≈ 0.9478673
b = 0.055 / 1.055 ≈ 0.0521327
c = 1 / 12.92   ≈ 0.0773994
d = 0.04045
e = 0
f = 0
```

> Display P3 与 sRGB 的传输函数**完全相同**，差异仅在于色域原色（primaries）。Display P3 使用 DCI-P3 原色覆盖更广色域，但编解码曲线是同一套。

阈值处连续：编码值 0.04045 → 线性值 ≈ 0.0031308

### 4.2 Rec.709 / Rec.2020

```
g = 20/9       ≈ 2.22222
a = 0.909672
b = 0.0903276
c = 1/4.5      ≈ 0.222222
d = 0.0812429
e = 0
f = 0
```

> Rec.2020（SDR）与 Rec.709 共用同一套传输函数参数。

阈值处连续：编码值 0.08124 → 线性值 ≈ 0.01805

### 4.3 对比总表

| 参数 | sRGB / Display P3 | Rec.709 / Rec.2020 | 纯 gamma 2.2 |
|------|-------------------|---------------------|---------------|
| **g** | 2.4 | 20/9 ≈ 2.222 | 2.2 |
| **a** | 1/1.055 ≈ 0.9479 | 0.90967 | 1.0 |
| **b** | 0.055/1.055 ≈ 0.0521 | 0.09033 | 0 |
| **c** | 1/12.92 ≈ 0.0774 | 1/4.5 ≈ 0.2222 | 0 |
| **d** | 0.04045 | 0.08124 | 0 |
| **e** | 0 | 0 | 0 |
| **f** | 0 | 0 | 0 |
| 过渡线性值 | ≈ 0.00313 | ≈ 0.01805 | — |

### 4.4 关键差异

1. **分段阈值不同**：sRGB 在暗部 4% 处就切换到幂段，Rec.709 要 8%。Rec.709 的暗部线性范围更大。
2. **线性段斜率不同**：sRGB 的 1/12.92 比 Rec.709 的 1/4.5 更平坦，暗部被提得更亮。
3. **整体 gamma 不同**：sRGB 的 2.4 > Rec.709 的 2.222，sRGB 亮部压得更暗。
4. **a,b 偏移不同**：sRGB 的偏移量（0.055/1.055）小于 Rec.709（0.0903），导致中灰位置的行为有细微差别。

### 4.5 skcms 参数提取对照

从 skcms 7 参数提取各色彩空间参数的方式：

**sRGB/Display P3**：`c = 1/12.92`，直接对应 `skcms_TransferFunction` 的 c；a,b,g,d 来自 7 参数的直接赋值。

**Rec.709/Rec.2020**：`c = 1/4.5`，`d = 0.0812429`。参数来自 Skia 源码中 `kRec709` 的定义，`kRec2020_10bit` 和 `kRec2020_12bit` 均直接引用 `kRec709`。

> 在 skcms 的内部实现中，`classify()` 函数根据参数特征将 `skcms_TransferFunction` 分派为 `sRGBish`、`PQish`、`HLGish` 等类型。sRGB 和 Rec.709 都属于 `sRGBish` 类型，即标准 7 参数形式。
